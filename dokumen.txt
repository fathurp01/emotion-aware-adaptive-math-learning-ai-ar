3.1 Struktur Repositori dan Persiapan Proyek
Implementasi sistem Emotion-Aware Adaptive Math Learning AI & AR Platform dilakukan menggunakan pendekatan cloud-native dengan struktur repositori terpusat. Repositori digunakan untuk menyimpan kode sumber frontend dan backend Next.js, skema basis data relasional Prisma, konfigurasi kontainer Docker, pipeline CI/CD GitHub Actions, manifest orkestrasi Kubernetes, konfigurasi monitoring Prometheus & Grafana, serta konfigurasi arsitektur cloud ter-peering menggunakan Terraform.
Struktur repositori disusun secara terstruktur sehingga setiap komponen (decoupled components) dapat dikembangkan secara mandiri namun tetap bersinergi di dalam repositori monolitik. Hal ini menyelaraskan proyek dengan standar arsitektur microservices dan cloud-native.

3.2 Persiapan Environment Variable Aplikasi
Tahap berikutnya adalah menyiapkan konfigurasi environment variable yang digunakan oleh frontend dan backend. Konfigurasi ini diperlukan agar aplikasi dapat terhubung dengan database, object storage multi-cloud, layanan AI, autentikasi, serta domain produksi.

3.3 Konfigurasi Dockerfile Frontend
Frontend aplikasi dikembangkan menggunakan Next.js dan dikemas ke dalam Docker container. Penggunaan Docker bertujuan agar aplikasi dapat dijalankan secara konsisten baik pada lingkungan lokal maupun server cloud.
Dockerfile frontend menggunakan pendekatan three-stage build (tiga tahap pembangunan) untuk menghasilkan image Docker yang sangat ringan dan teroptimasi:
1. Stage 1 (deps): Hanya melakukan instalasi *node_modules* bersih menggunakan perintah npm ci berdasarkan package.json untuk memanfaatkan cache Docker layer.
2. Stage 2 (builder): Menyalin *dependencies* dari Stage 1, memindahkan seluruh source code program, dan melakukan kompilasi aplikasi Next.js (npm run build).
3. Stage 3 (runner): Menyusun lingkungan produksi minimal, menyalin hasil kompilasi folder .next, folder public (termasuk model AI lokal), serta pustaka tambahan seperti lib dan utils, kemudian mengekspos port 3000.
Konfigurasi Dockerfile frontend yang digunakan adalah sebagai berikut:
# Stage 1: Install dependencies
FROM node:20-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm config set registry https://registry.npmmirror.com && npm ci
 
# Stage 2: Build the application
FROM node:20-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
 
# Build Next.js
ENV NEXT_TELEMETRY_DISABLED=1
RUN npm run build
 
# Stage 3: Runner
FROM node:20-alpine AS runner
WORKDIR /app
 
ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1
ENV PORT=3000
ENV HOSTNAME="0.0.0.0"
 
COPY --from=builder /app/package*.json ./
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/public ./public
COPY --from=builder /app/scripts ./scripts
COPY --from=builder /app/lib ./lib
COPY --from=builder /app/utils ./utils
 
EXPOSE 3000
 
CMD ["npx", "next", "start", "-p", "3000"]

Sebelum konfigurasi Dockerfile frontend ditampilkan, dilakukan pengecekan terhadap file model TensorFlow.js yang berada pada direktori frontend/public/model/tfjs_model. Model ini digunakan sebagai *self-hosted AI model* untuk mendeteksi emosi siswa secara langsung di browser.
  
Gambar 3.3 Konfigurasi Dockerfile Frontend dan Model TensorFlow.js
Berdasarkan Gambar 3.3, Dockerfile frontend telah dikonfigurasi untuk membangun aplikasi Next.js pada mode produksi. Selain itu, model TensorFlow.js disimpan pada direktori publik sehingga dapat dimuat oleh browser siswa ketika fitur deteksi emosi digunakan. 3.4 Konfigurasi Dockerfile Backend
Backend aplikasi bertugas menangani autentikasi, koneksi database, integrasi object storage, integrasi LLM, pengolahan kuis adaptif, remedial personal, dan penyimpanan log emosi siswa. Backend juga dikemas menggunakan Docker agar dapat dideploy secara konsisten di server cloud.
Sama dengan frontend, Dockerfile backend dikonfigurasi menggunakan metode three-stage build untuk meminimalisasi ukuran container dan menjaga dependensi tetap terisolasi:
1. Stage 1 (deps): Melakukan instalasi dependensi bersih dari package.json untuk optimasi caching Docker layer.
2. Stage 2 (builder): Menghasilkan Prisma Client (npx prisma generate) agar backend dapat menerjemahkan skema data database MySQL, kemudian melakukan build aplikasi Next.js/Server API.
3. Stage 3 (runner): Menyalin modul node_modules produksi, hasil build .next, folder prisma, serta folder penunjang seperti scripts, lib, dan utils. Tahap ini mengekspos port 5000 untuk melayani REST API.
Konfigurasi Dockerfile backend yang digunakan adalah sebagai berikut:
# Stage 1: Install dependencies
FROM node:20-alpine AS deps
WORKDIR /app
COPY package*.json ./
RUN npm config set registry https://registry.npmmirror.com && npm ci
 
# Stage 2: Build the application
FROM node:20-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
 
# Generate Prisma Client
RUN npx prisma generate
 
# Build Next.js
ENV NEXT_TELEMETRY_DISABLED=1
RUN npm run build
 
# Stage 3: Runner
FROM node:20-alpine AS runner
WORKDIR /app
 
ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1
ENV PORT=5000
ENV HOSTNAME="0.0.0.0"
 
COPY --from=builder /app/package*.json ./
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/public ./public
COPY --from=builder /app/prisma ./prisma
COPY --from=builder /app/scripts ./scripts
COPY --from=builder /app/lib ./lib
COPY --from=builder /app/utils ./utils
 
EXPOSE 5000
 
CMD ["npx", "next", "start", "-p", "5000"]

Backend membutuhkan Prisma Client agar dapat berkomunikasi dengan database MySQL. Oleh karena itu, perintah npx prisma generate dijalankan pada tahap build (Stage 2).

3.5 Konfigurasi Docker Compose Lokal
Sebelum aplikasi dideploy ke cloud, dilakukan pengujian lokal menggunakan docker-compose.yml. Pengujian lokal bertujuan untuk memastikan bahwa frontend, backend, dan database dapat berjalan serta saling terhubung secara harmonis dalam satu virtual network lokal.
Contoh konfigurasi docker-compose.yml yang digunakan adalah sebagai berikut:
version: '3.8'
 
services:
  mysql:
    image: mysql:8.0
    container_name: emotion_learning_db
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: password
      MYSQL_DATABASE: emotion_learning_db
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql
 
  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    container_name: adaptive_learning_backend
    restart: always
    ports:
      - "5000:5000"
    environment:
      - DATABASE_URL=mysql://root:password@mysql:3306/emotion_learning_db
      - GEMINI_API_KEY=your_gemini_api_key_here
      - NVIDIA_API_KEY=SENSOR_NVIDIA_API_KEY
      - NVIDIA_MODEL=meta/llama-3.1-8b-instruct
      - MISTRAL_API_KEY=your_mistral_api_key_here
      - AUTH_SECRET=SENSOR_AUTH_SECRET
      - MATERIAL_PRECOMPUTE_ON_STARTUP=1
    depends_on:
      - mysql
 
  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile
    container_name: adaptive_learning_frontend
    restart: always
    ports:
      - "3000:3000"
    environment:
      - BACKEND_API_URL=http://backend:5000
      - AUTH_SECRET=SENSOR_AUTH_SECRET
      - NEXTAUTH_SECRET=SENSOR_AUTH_SECRET
      - NEXT_PUBLIC_APP_URL=http://localhost:3000
    depends_on:
      - backend
 
volumes:
  mysql_data:

Setelah file docker-compose.yml disiapkan, seluruh grup container dijalankan secara lokal menggunakan perintah berikut:
docker compose up -d --build

Untuk melihat status container yang sedang aktif berjalan di sistem:
docker ps

Untuk melacak logs aktivitas API Backend secara real-time:
docker logs -f adaptive_learning_backend

Untuk melacak logs aktivitas render Frontend Next.js secara real-time:
docker logs -f adaptive_learning_frontend

3.8 Build Image Docker Frontend dan Backend (Opsi Lokal & Awan)
Proses pembuatan image Docker untuk frontend dan backend dapat dilakukan melalui dua pendekatan: Opsi Manual (Lokal) untuk keperluan debugging pengembang, dan Opsi Otomatis (Awan/CI-CD) untuk integrasi sistem produksi.
A. Opsi Manual (Lokal):
Proses ini dilakukan di komputer pengembang menggunakan CLI Docker Desktop dengan perintah sebagai berikut:
Perintah build image frontend:
docker build -t username/adaptive-math-frontend:latest ./frontend

Perintah build image backend:
docker build -t username/adaptive-math-backend:latest ./backend

Setelah proses build selesai, daftar image dapat diperiksa menggunakan perintah:
docker images

B. Opsi Otomatis (GitHub Actions):
Pada praktiknya, proses build secara lokal sering kali menemui kendala batas waktu koneksi (*ETIMEDOUT*) saat mengunduh package dependencies yang besar (seperti TensorFlow.js) dari dalam virtualisasi WSL2 Windows. Oleh karena itu, pendekatan terbaik dan paling stabil adalah mendelegasikan proses build ini secara otomatis ke runner GitHub Actions di awan yang memiliki koneksi internet giga-bit (dijelaskan detail di Bab 3.27).

docker login

Tag image frontend:

3.10 Persiapan Infrastruktur AWS
Infrastruktur utama aplikasi dijalankan menggunakan AWS sebagai penyedia layanan compute dan database. Komponen yang digunakan adalah:
1. EC2 untuk menjalankan container frontend dan backend.
2. RDS MySQL untuk database produksi terkelola.
3. VPC untuk segmentasi jaringan aman.
4. Subnet untuk pemisahan jaringan publik dan privat.
5. Security Group untuk mengatur akses port.
6. IAM untuk pengaturan hak akses.
Pada rancangan akhir, AWS digunakan sebagai main compute provider untuk EC2, VPC, dan RDS MySQL. Cloudflare R2 digunakan sebagai object storage provider, sedangkan Cloudflare CDN digunakan sebagai DNS, CDN, SSL/TLS, dan reverse proxy. Dengan pendekatan ini, sistem memenuhi prinsip multi-cloud karena compute dan database tidak berada pada provider yang sama dengan object storage.
3.11 Konfigurasi VPC pada AWS Menggunakan Terraform (Infrastructure as Code)
Tahap pertama pada infrastruktur AWS adalah menyiapkan segmentasi jaringan menggunakan VPC. Pada tahap ini, resource AWS tidak dibuat secara manual satu per satu melalui AWS Console, melainkan dideklarasikan melalui Terraform. Dengan demikian, Terraform berperan sebagai alat Infrastructure as Code yang mengirim instruksi provisioning dari komputer lokal ke AWS API.

3.16 Konfigurasi Cloudflare R2 sebagai Object Storage Multi-Cloud
Object storage tidak dibuat melalui Terraform AWS karena ketentuan UAS mewajibkan bucket/object storage menggunakan cloud provider berbeda dari layanan utama aplikasi. Cloudflare pada rancangan ini memiliki dua peran, yaitu sebagai penyedia object storage melalui R2 dan sebagai penyedia CDN, DNS, SSL/TLS, serta reverse proxy.
1. Masuk ke Cloudflare Dashboard menggunakan akun Cloudflare.
2. Pilih menu R2 Object Storage, kemudian buka halaman bucket.
3. Buat bucket baru dengan nama adaptive-learning-assets-multi-cloud atau nama bucket yang disesuaikan dengan domain publik media.
4. Buat R2 API Key dengan hak akses read-write ke bucket.
5. Catat endpoint Cloudflare R2, R2 Access Key ID, dan R2 Secret Access Key yang akan digunakan backend melalui S3-Compatible API.
6. Konfigurasikan domain CDN publik, misalnya media.domain-kamu.com, melalui Cloudflare agar aset dari Cloudflare R2 dapat disajikan melalui CDN.

3.26 Konfigurasi GitHub Secrets untuk CI/CD

• `FRONTEND_PUBLIC_DOMAIN`: Domain publik aplikasi frontend (node-f3a17c.my.id).
• `EC2_USERNAME`: Nama pengguna SSH server EC2 (ubuntu).
• `EC2_SSH_KEY`: Kunci privat SSH (.pem) untuk masuk ke kedua instance EC2.

3.27 Konfigurasi Pipeline CI/CD GitHub Actions
Pipeline CI/CD dideklarasikan dalam berkas konfigurasi .github/workflows/ci-cd.yml. Pipeline ini terbagi ke dalam 3 pekerjaan utama: Test (melakukan pengujian build frontend/backend), Dockerize (membangun image Docker dan mempublikasikannya ke Docker Hub), serta Deploy (menghubungkan server EC2 melalui SSH untuk melakukan pembaruan kontainer secara otomatis).

Berikut adalah isi konfigurasi lengkap file .github/workflows/ci-cd.yml:
name: CI/CD Pipeline

on:
  push:
    branches: [ "main", "cloud" ]
  pull_request:
    branches: [ "main", "cloud" ]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'
          cache-dependency-path: |
            backend/package-lock.json
            frontend/package-lock.json

      - name: Test Backend Build
        run: |
          cd backend
          npm ci
          npx prisma generate
          npm run build

      - name: Test Frontend Build
        run: |
          cd frontend
          npm ci
          npm run build

  dockerize:
    needs: test
    runs-on: ubuntu-latest
    if: github.event_name == 'push'
    steps:
      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      - name: Build and Push Backend Image
        uses: docker/build-push-action@v5
        with:
          context: ./backend
          file: ./backend/Dockerfile
          push: true
          tags: |
            ${{ secrets.DOCKER_USERNAME }}/adaptive-math-backend:latest
            ${{ secrets.DOCKER_USERNAME }}/adaptive-math-backend:${{ github.sha }}

      - name: Build and Push Frontend Image
        uses: docker/build-push-action@v5
        with:
          context: ./frontend
          file: ./frontend/Dockerfile
          push: true
          tags: |
            ${{ secrets.DOCKER_USERNAME }}/adaptive-math-frontend:latest
            ${{ secrets.DOCKER_USERNAME }}/adaptive-math-frontend:${{ github.sha }}

  deploy:
    needs: dockerize
    runs-on: ubuntu-latest
    if: github.event_name == 'push'
    steps:
      - name: Setup SSH Key
        run: |
          mkdir -p ~/.ssh
          echo "${{ secrets.EC2_SSH_KEY }}" > ~/.ssh/id_rsa
          chmod 600 ~/.ssh/id_rsa
          ssh-keyscan -H ${{ secrets.EC2_BACKEND_HOST }} >> ~/.ssh/known_hosts
          ssh-keyscan -H ${{ secrets.EC2_FRONTEND_HOST }} >> ~/.ssh/known_hosts

      - name: Deploy Backend to Backend EC2
        run: |
          ssh -i ~/.ssh/id_rsa ubuntu@${{ secrets.EC2_BACKEND_HOST }} 'bash -s' << 'EOF'
            sudo mkdir -p /app/emotion-aware-adaptive-math-learning-ai-ar
            sudo chown -R ubuntu:ubuntu /app/emotion-aware-adaptive-math-learning-ai-ar
            cd /app/emotion-aware-adaptive-math-learning-ai-ar
            if [ ! -d .git ]; then
              git init
              git remote add origin https://github.com/fathurp01/emotion-aware-adaptive-math-learning-ai-ar.git
              git fetch origin cloud
              git checkout -f -B cloud origin/cloud
            else
              git pull origin cloud
            fi
            export DOCKER_USERNAME=${{ secrets.DOCKER_USERNAME }}
            docker compose -f docker-compose.backend.yml pull
            docker compose -f docker-compose.backend.yml down
            docker compose -f docker-compose.backend.yml up -d
            docker compose -f docker-compose.backend.yml exec -T backend npx prisma db push
            docker compose -f docker-compose.backend.yml exec -T backend npx prisma db seed
            docker system prune -a -f
          EOF

      - name: Deploy Frontend to Frontend EC2
        run: |
          ssh -i ~/.ssh/id_rsa ubuntu@${{ secrets.EC2_FRONTEND_HOST }} 'bash -s' << 'EOF'
            sudo mkdir -p /app/emotion-aware-adaptive-math-learning-ai-ar
            sudo chown -R ubuntu:ubuntu /app/emotion-aware-adaptive-math-learning-ai-ar
            cd /app/emotion-aware-adaptive-math-learning-ai-ar
            if [ ! -d .git ]; then
              git init
              git remote add origin https://github.com/fathurp01/emotion-aware-adaptive-math-learning-ai-ar.git
              git fetch origin cloud
              git checkout -f -B cloud origin/cloud
            else
              git pull origin cloud
            fi
            export DOCKER_USERNAME=${{ secrets.DOCKER_USERNAME }}
            export BACKEND_PRIVATE_IP=${{ secrets.EC2_BACKEND_PRIVATE_IP }}
            export FRONTEND_PUBLIC_DOMAIN=${{ secrets.FRONTEND_PUBLIC_DOMAIN }}
            docker compose -f docker-compose.frontend.yml pull
            docker compose -f docker-compose.frontend.yml down
            docker compose -f docker-compose.frontend.yml up -d
            docker system prune -a -f
          EOF

3.29 Konfigurasi Monitoring Prometheus dan Grafana
Monitoring sistem digunakan untuk memantau status kesehatan instance, metrik penggunaan CPU/RAM, serta ketersediaan kontainer backend secara realtime. 

Metrik ditarik menggunakan kontainer monitoring yang diatur pada file monitoring/docker-compose.monitoring.yml di server EC2 Frontend:
version: '3.8'

services:
  prometheus:
    image: prom/prometheus:latest
    container_name: adaptive_learning_prometheus
    restart: always
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
    ports:
      - "9090:9090"
    networks:
      - adaptive-learning-net

  grafana:
    image: grafana/grafana:latest
    container_name: adaptive_learning_grafana
    restart: always
    ports:
      - "3001:3000"
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=SENSOR_GRAFANA_PASSWORD
    depends_on:
      - prometheus
    networks:
      - adaptive-learning-net

networks:
  adaptive-learning-net:
    name: emotion-aware-adaptive-math-learning-ai-ar_default
    external: true

Karena server frontend dan backend berjalan secara terpisah pada subnet VPC yang berbeda, kontainer Prometheus yang dijalankan di server Frontend tidak dapat melakukan resolusi nama kontainer `backend` secara langsung melalui internal DNS Docker. Sebagai solusinya, pemantauan dilakukan melalui rute VPC Peering dengan menggunakan IP privat dari server EC2 Backend (10.2.1.186:5000).

Berikut adalah konfigurasi file monitoring/prometheus.yml yang disinkronkan:
global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090']

  - job_name: 'adaptive-learning-backend'
    metrics_path: '/api/health'
    static_configs:
      - targets: ['10.2.1.186:5000']

Jalankan monitoring di server EC2 Frontend:
cd /app/emotion-aware-adaptive-math-learning-ai-ar/monitoring
docker compose -f docker-compose.monitoring.yml up -d

3.30 Konfigurasi Kubernetes Manifest sebagai Bonus
Selain deployment menggunakan Docker Compose, proyek ini menyediakan manifestasi orkestrasi Kubernetes (k8s) lengkap pada direktori /k8s sebagai bentuk kesiapan arsitektur sistem untuk skala besar (enterprise scaling).

Manifes yang disediakan meliputi:
1. database.yaml: Menggunakan StatefulSet dengan volume PersistentVolumeClaim (PVC) sebesar 10Gi untuk menjaga database MySQL tetap persisten saat kontainer mengalami kegagalan.
2. backend.yaml: Mengatur replika minimal sebanyak 2 pod backend Next.js API. Dilengkapi HorizontalPodAutoscaler (HPA) untuk melakukan scale-out pod otomatis hingga 10 pod ketika rata-rata utilitas CPU pod backend menyentuh angka 75%.
3. frontend.yaml: Deployment pod frontend Next.js yang menangani traffic web siswa.
4. ingress.yaml: Ingress controller berbasis Nginx yang melakukan reverse proxy domain luar ke internal frontend-service port 3000.

Contoh deklarasi HPA di dalam k8s/backend.yaml:
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: backend-hpa
  namespace: default
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: adaptive-math-backend
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 75
